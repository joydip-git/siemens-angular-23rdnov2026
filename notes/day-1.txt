Binding:
----------------
1. pass data from code of the component to the template of the same component
	- data binding
	syntax: {{ prop-name }} -> interpolation
		<element [attribute]="prop-name"> -> property binding

	note: interpolation converts any value to string which property bidning does not

2. pass data from template of the component to the code of the same component
	event binding:
	<element (event)="method-of-class(args)">

signals:
WritableSignal: mutable
signal() -> call this method a pass a default initial value
	a. set method
	b. update method

Computed Signal: not mutable directly
computed() ->  it is used create another signal whose value is calculated/derived from another signal. you must pass a callback function with logic to derive a new value for this signal based on other signal/signals. the callback method MUST return a new value

effect() -> just a function which is used to register a callback function with angular runtime and this callback function generally involves one or more than one signal. the callback function is re-executed every time value of any of the involved signals is changed
the callback method MUST NOT return any value


directive:
	it is used as custom HTML attribute (which only angular understands)

	a. structural directive: always used with *. it is used to manipulate DOM elements.
	*ngFor, *ngIf, *ngSwitch etc.

	@Directive({
		selector:'[ngIf]'
	})
	export class NgIf{
	}


	b. attribute directive: these directives are used like an attribute to an element, but does extend the behavior of that element
	it is NOT used with any special character
	<element routerLink="/url">
